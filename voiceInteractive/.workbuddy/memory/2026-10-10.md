## 代码架构梳理（只读分析，未改动代码）

项目：叮咚AI / MEIZHOU AI 语音交互（Windows 桌面 + 浏览器前端）。

- 双进程结构：
  - 主进程 `run.py → assistant.main`：`dashboard.py`(静态托管 :8765 + `/srs/*` 反向代理)、`tray.py`(pystray 托盘)、`lifecycle.py`(shutdown/restart 事件)、`native_camera.py`(仅 OpenCV 探测)。不 import torch。
  - ASR 子进程 `python -m assistant.asr_server`（:8770）：torch + `models/Qwen3-ASR-0.6B`(fp16/cuda)、edge-tts、PyAV 解码、`RemoteCameraRegistry`(go-proxy 登录拉流)。端点 `/transcribe /tts /chat /vision /vision_save /cameras /log /ready`。
  - `llm.py` 的 OllamaClient 被两个进程各自 import，无共享状态；`vision()` 优先走远端 qwen3-vl API，失败回退本地。
- 前端 `web/`：index.html + 7 个全局函数式 JS（无模块打包）：`voice-utils / voice-rules / index-ui / index-cam / voice-srs / index-voice / index-inspect`。浏览器直连 8765 取页面、直连 8770 调 API、直连 SRS UDP 8000 拉 WebRTC 流。
- 外部依赖：Ollama :11434、SRS :1985(信令)/UDP 8000(媒体)、go-proxy :51351。
